Jacaranda2FA 01.00.04 — Trusted Browser Regression Correction

This maintenance release corrects the trusted-browser regression introduced by
the 01.00.01 verification-screen state refactor.

Root cause:
- 01.00.00 used the checked checkbox / raw Request.Form checkbox field directly
  when deciding whether to create a trusted-browser token.
- 01.00.01 replaced that proven path with a Session-based preference helper.
- The 01.00.02 and 01.00.03 hidden-field changes improved redirect state handling
  but still did not restore the original checkbox-post path as the primary source.
- As a result, Remember this browser for 2FA could evaluate false for authenticator,
  email OTP and recovery-code verification.

01.00.04 fix:
- Restores the exact proven 01.00.00 concept as the first check:
  chkTrustBrowser.Checked OR Request.Form[chkTrustBrowser.UniqueID] present.
- A checked/posting checkbox immediately records TrustBrowserRequested = true.
- The hidden 1/0 preference remains only as redirect-state support for the
  authenticator -> email workflow.
- Session state is used only when no explicit checkbox or hidden preference is
  present.
- The common trusted-browser token-creation routine is unchanged.

Security boundary unchanged:
- DNN password validation is still required first.
- Trusted-browser creation occurs only after successful second-factor verification.
- HTTPS-only issuance, Secure/HttpOnly cookie handling, hashed token storage,
  expiry and revocation are unchanged.

No database schema changes.
No new SQL migration.
No TOTP, email OTP, recovery-code, throttling, policy or cryptographic changes.
