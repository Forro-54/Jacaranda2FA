Jacaranda2FA 01.00.00 — First Public Test Release

Jacaranda2FA is a community two-factor authentication extension for DNN Platform.

Tested successfully on:
- DNN Platform 10.3.2
- DNN Platform 10.3.3
- The stock/default DNN skin
- A production-style custom Bootstrap 5 skin

Authentication methods tested:
- Microsoft Authenticator
- Google Authenticator
- Email one-time verification codes
- One-time recovery codes
- Trusted/remembered browsers

01.00.00 promotes the confirmed-working 00.00.31 development baseline to the
first public test release. There are no authentication, security-model,
cryptographic, throttling, trusted-browser, recovery-code, TOTP, or database
schema changes from 00.00.31.

Key capabilities:
- DNN username/password validation remains under DNN control.
- TOTP authenticator-app verification with replay protection.
- Email OTP fallback.
- One-time recovery codes.
- Optional trusted-browser bypass after successful password validation.
- Role-based 2FA enforcement.
- Persistent cross-challenge second-factor throttling.
- Security audit logging and configurable security controls.
- User-facing Account Security module for authenticator, recovery-code and
  trusted-browser management.
- Responsive login and verification controls compatible with stock DNN 10.3.x.

PUBLIC TEST RELEASE
Administrators should first install and test Jacaranda2FA in a staging or test
environment. Keep a logged-in SuperUser session available during initial
configuration.

IMPORTANT ENFORCEMENT NOTE
Jacaranda2FA can enforce 2FA only on authentication paths that pass through
Jacaranda2FA. If DNN Normal Login or another independent authentication provider
remains enabled, users may be able to authenticate through that provider without
Jacaranda2FA. Test all enabled authentication routes before relying on mandatory
2FA enforcement.

RECOVERY PRECAUTION
Before disabling alternative authentication providers, confirm that at least one
SuperUser can successfully sign in through Jacaranda2FA and retains a usable
authenticator, email fallback or unused recovery code.

EMAIL FALLBACK
Email OTP is provided as a practical fallback. For higher-assurance accounts,
an authenticator app plus securely stored recovery codes is preferred.

No new SQL migration is introduced by 01.00.00. The installer retains the
existing consolidated migrations required by the working release lineage.
